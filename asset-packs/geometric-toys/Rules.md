# Bongo Planet — executable rules

Topology `icosa-3v-v1` is a normalized frequency-three icosahedron, with deterministic traversal IDs 0–91. Composition axes are right/forward/up; Three.js maps (x,z,-y). Angular reach includes a 1e-9 radian tolerance. Scene versions 1 and 2 are strictly validated, unknown fields rejected, one piece per slot, unique stable piece IDs. Scene data excludes cameras, transport and endpoints. The [creation guide](Creation-Guide.md) explains chords, the shared grid and rhythmic alignment for humans and agents.

## Portable compositions and agent instructions

App Save and Export serialize a strict envelope `{format: "bongo-planet-composition", version: 1, scene, appearance}`. The agent guide describes the current gated scene contract, `scene.version: 2`. Appearance uses version 1 and the current Geometric Toys/seams/struts contract, including instrument/planet colors, backdrop, spark style, gate icon and switch styling, size and lighting; eyes and bounce are always on. The current look schema in `src/view/art/appearance.ts` defines allowed fields and ranges. Visual settings never affect musical routing or time. No camera, playback state, samples, credentials or output endpoint is saved.

Import and Load validate the entire envelope before replacing music or look, and load paused. Invalid JSON, unknown fields, invalid appearance, occupancy or topology leave both intact. Scene history handles musical scenes; look edits and imported appearance use their independent automatic browser save. Standalone look files transfer appearance alone.

The canonical agent file reference is generated [Agent-Guide.md](Agent-Guide.md). The separate AI music page at `/BongoPlanet/ai-music/` uses the same FAQ, schemas, catalogs, neighbor map and creation-guide text. Presets links to that page in a new tab, preserving the open composition. Build regenerates the document; composition-file tests detect stale references. Behavior changes require updating this contract and `Creation-Guide.md`; option changes require updating their catalogs and validators. Keep the generated agent guide current with `npm run docs:agents`.

Planet swatches use a dedicated dark palette, retaining Planet blue (`#5262e9`) and Ink (`#344362`); instrument swatches keep their bright palette. All five backdrop choices use dark gradients, with Midnight as the default and Star field retained. Backdrop IDs stay compatible with existing files. Imported custom hex colors remain supported. The current catalogs live in `src/view/art/swatches.ts`.

Off-state gate contours use Whisper half pixel: 0.5 CSS pixels at 25% opacity, with `switches.stroke` multiplying that base width. The renderer converts the width through the orthographic camera's current zoom and viewport height, compensating for glyph size. Flat contours naturally foreshorten near the globe's edge. The look editor uses the same width and opacity. On-state glyphs keep their opaque fill; saved `offColor` and `onColor`, glyph shape, picking targets and wiring remain unchanged. The fixed rendering treatment adds no serialized field.

## Instrument playback

The catalog contains Guitar, Glass, Kalimba, Piano and Marimba, plus High bongo (`bongo-high`), Low bongo (`bongo-low`), Kick (`kick`), Snare (`snare`) and closed Hi-hat (`hi-hat`). All current instruments serialize as `kind: "note"` with their instrument ID; labels and companion trigger packets accept the same catalog. Legacy beat migration remains unchanged.

Percussion uses the prepared CC0 mono PCM recordings in `public/audio/percussion/`. Each accepted hit alternates between its two takes, plays at source speed regardless of key/scale/degree/octave, and ends at that take's natural sample boundary regardless of saved note-length metadata. The prepared onset/quiet-tail fades are retained without an extra synthesized attack. Level, master protection, per-node/per-generator cancellation, the 20 ms release and the 64-voice cap still apply. Separate arrivals remain separate voices; there is no global drum choke group. Optional open-hat recordings remain research assets.

Percussion colors are added to version-one looks with defaults, so earlier complete music-and-look files and standalone looks retain their existing colors and load correctly. Percussion selection, labels and colors round-trip through the composition file; the generated agent reference includes these instruments and behavior.

On the planet and in exported models, percussion playing surfaces face local +Z, away from the planet, with eyes on the outward face. Palette portraits use the same meshes in their original upright pose.

Percussion trigger duration reports the longest take rounded up to a millisecond, rather than the saved note-length metadata. This keeps local/companion source ownership and cancellation valid for the entire tail. The synth ends each voice at its selected take's exact boundary.

## Current gated playback and shared musical grid

Fresh compositions use `version: 2`, `settings.propagation: "gated"` and directed junction wiring. Every completed adjacent crossing takes **0.25 quarter-note beats: one sixteenth note**, including empty vertices and revisits. At fixed BPM this is `15 / BPM` seconds, or 125 ms at 120 BPM. Neither geometric distance nor generator interval/travel changes that duration. Equal-hop branches from the same launch time arrive simultaneously and retain separate voices and provenance.

Generators share one transport and a grid anchored at beat zero. Periods are 1/2/3/4/6/8 beats. The saved fractional phase is interpreted as `round(phase * period / 0.25) * 0.25`, modulo period, with upward midpoint ties. The original phase value remains in the scene. Added/enabled/period/phase-edited generators join their next eligible strictly future boundary. Initial playback includes the beat-zero boundary. Pause discards active sparks; resume preserves beat and joins future boundaries without replay. Load/Clear reset beat zero.

Tempo edits apply at the next integer beat. Because emissions and hop completions lie on sixteenth-note boundaries, committed edges finish at that boundary and subsequent edges of **all active sparks**, including Infinite circuits, use the new BPM. A tempo anchor and exact hop counts determine deadlines; repeated duration addition must not cause long circuits to drift from new emissions. Generator interval, enabled state and travel edits affect subsequent emissions. Travel is a positive safe integer or `"infinite"`; every split inherits the used/remaining budget.

Each arrival plays its current destination instrument, then checks its travel budget and outgoing gates. All enabled exits receive a child; none means stop. Arrivals at the same time are processed in stable acceptance order and never musically deduplicated. Passing a generator is silent and does not emit a new pulse. The engine commits one edge ahead, preserving committed sound parameters for an unchanged occupant; live occupant changes reconcile pending triggers. Deleting a generator cancels its descendants. Work/edge/arrival/pending limits pause explicitly on overload.

The renderer uses the audio engine's departure/arrival timestamps. Longer struts have higher visual speed; `GatedEdge.speed` is derived from the current edge length and duration and must never determine musical delay. The old `settings.quantization` and scene-level fractional `travel` fields are compatibility metadata and do not alter gated timing. F15/F16/F17 exercise current gated playback. Existing version-two saves adopt this timing rule; version-one saves keep their legacy behavior until a gate edit explicitly converts them.

Gated limits are 256 active edges, 2,016 arrivals in a rolling audio second, 5,376 pending sounds and **64 decisions per actual audio quantum**. Master-boundary decisions count too. These are independent bounds; synchronized arrivals can reach the work limit before the edge limit. Prospective splitting is checked before inserting children. Exceeding a bound pauses with a visible reason, clears propagation/pending work and releases sound; Play after simplifying starts a fresh session without replay. The 64-decision bound follows the measured dense trace in `evidence/spark-gates/step-03/qualified-worklet-budget/report.json`.

Reliable audio-event retention is capped at 2,048 records. Load, Clear, Pause and interruption advance the adapter's transport epoch; old event/status messages are acknowledged but ignored. Deleting a source releases its owned local and remote voices even after many intervening short sounds. Internal source-ownership metadata is resolved into ordinary cancel IDs before wire serialization. Output ownership retention has its own 23,520-record bound and explicit disconnect policy.

## Legacy version-one route journeys and painted seams

F10 and existing version-one scenes with `settings.propagation = "routes"` retain route journeys. Original scenes without that optional field, or with `"radial"`, retain the original musical rules described below. Propagation remains serialized with the composition and participates in Undo/Redo; the toy UI does not expose a behavior selector. Editing a gate converts a legacy scene into gated routing; Undo restores the original paused. Appearance is separate.

Route journeys launch one spark per outgoing route rather than one per sound target. A deterministic shortest-path tree within angular reach partitions vertices by the generator's first neighboring edge. Each sector is traversed by one continuous walk, with direction changes/backtracking to reach its remaining branches; no spark copies are created. The walk ends at its final new vertex. Routes depend only on source and reach, not instrument placement. Passing a note or drum produces a sound on every encounter, including a repeated encounter when the walk returns through that vertex. Other generators and empty vertices are silent.

All routes in one emission share a speed: longest route length divided by period-seconds × travel-fraction. Length is the sum of straight unit-sphere chord lengths. At unchanged settings, every spark finishes within the selected fraction of its generator cycle. Tempo/reach/period changes affect later emissions; existing journeys retain their committed times. Separate generators can have independent periods. Route hits use the particle's physical passage times; rhythm quantization applies only to Original pulses.

At emission, route visits schedule sound snapshots at cumulative distance / speed. Moving a piece cancels its old future route hits and schedules remaining visits at its new vertex; the paths and particle IDs remain unchanged. Newly placed pieces join remaining visits. Deleting a sound cancels its hits while the route continues; deleting its generator stops its journeys. Disable permits committed journeys to finish. Switching propagation modes cancels outstanding work/releases voices but preserves transport beat. Pause/load/clear/interruption clear journeys.

Maximum active journey state: 256; maximum pending sound triggers: 5,376; either capacity overflow pauses with a recoverable visible error. Each route has at most 182 vertex entries. At fixed settings, the eight-generator full-sphere maximum scene has at most 48 journeys. Up to 128 visible particles share fixed render buffers. The Original-pulse event-rate budget below is not a route-mode event-rate claim: revisited vertices can produce additional sounds.

Painted seams use exactly the faceted planet's radius-0.99 vertex coordinates and one straight segment per topology edge. The globe uses polygon depth offset so those coplanar seams render cleanly without a second floating grid. Placement dots share the junction coordinates. Geometric Toys with painted seams is the only supported appearance; older appearance presets migrate to it. The renderer samples each route from audio-supplied passage times and uses the same selected connection geometry. Constant physical speed applies only to these legacy version-one journeys; current gated scenes use equal musical hop duration.

## Legacy scene pulse behavior

Surface arcs default to unit radius after the composition-to-render axis transform. Rendered connection lines explicitly use radius 1, above the opaque globe's radius 0.993. Their 48 segments keep even antipodal line interiors outside that globe. The decorative grid and expanding wavefront use separate visual offsets; musical coordinates, manual-move interpolation and output XYZ remain on the unit sphere. Unit-path tests and actual connection-buffer checks cover the required surface geometry.

The Work-Package prototype table applies. Supported limits: 92 pieces, at most 8 generators, 40–180 BPM, periods 1/2/3/4/6/8, phase [0,1), reach [0,180°], travel [0.25,0.75], quantization off/0.125/0.25 beats. Notes use degrees 0–6, octaves 2–6, sine/triangle, 0.05–8 second duration, levels [0,1]; beats kick/hat/snare, 0.03–4 second decay. Degrees wrap within the selected scale, raising an octave for overflow. Maximum simultaneous generator×target fanout is 8×84=672, with 2016 committed triggers/second at 180 BPM and period 1. Maximum pending committed triggers is 5376; hitting the bound produces a visible error and pauses. F08 uses 8 generators and 84 long-release targets; F06 retains its four-generator definition. F09 uses period-8 pulses followed by a tempo increase to exercise overtaking/queue capacity.

Transport uses an injected monotonic clock. Emissions commit at their logical boundary, never at a visual frame or a long lookahead preparation. Live synthesis and engine tick inside the audio render thread, once per render quantum; main-thread stalls cannot stop ordinary playback. UI edits apply on receipt at the next audio quantum. An edit exactly at a processed emission is post-emission. Added/enabled/period/phase-edited generators join the next boundary strictly after the current beat; a fresh first-generator start emits at beat zero. Tempo changes apply at the next integer beat, preserving accumulated beats; committed onsets retain seconds. At constant tempo, travel/quantization stays strictly within each period. Ties round upward. Key/sound snapshots commit at emission, positions are refreshed at onset.

Pause cancels all pending triggers and releases voices with a 20ms fade (below 100ms). Resume retains beat, joins future boundaries, and never replays elapsed emissions. Clear/load increment session identity, reset beat zero and release voices. Load starts paused; undo Clear and undo/redo load restore through a paused scene replacement. Disable leaves committed pulses intact; deleting a generator cancels its pending children; deleting a target cancels pending and releases active voices. Ordinary edit undo is a new scene edit and cannot replay cancelled pulses. Replacing a piece kind under the same ID cancels the former piece’s work and recreates its visual. History holds 100 scene edits, with sliders committing one change per completed gesture. Cancelled/invalid input leaves the model unchanged.

Voice cap 64. Steal the oldest active voice by onset then sequence; deterministic and counted. Peak protection is a bounded mono saturator with ceiling 0.98, master gain after summing. Late events over 20ms are dropped and counted, never squeezed into a catch-up burst; engine suspension pauses instead of iterating missed emissions. Audio interruption requires explicit Play/Enable sound. Activation is attempted only in a deliberate user gesture.

Every explicit Play waits for 250ms of stable audio-render quanta before starting musical time. Activation during module loading preserves the most recent intent; load, Clear, interruption, or capacity failure cancels that intent. A render-clock gap over100ms resets stability and requires another deliberate Play. This warm-up addresses an observed Safari startup clock discontinuity; it does not reduce the onset-error budget after transport starts. Processor failure/interruption disconnects local output immediately so remote playback cannot survive a failed local clock.

## Editing and camera gestures

A floating striped North Pole model marks composition +Z (rendered +Y), with a clear gap above the globe. Its N plaque turns around that fixed axis to face the camera. The default framing fits the globe and marker in landscape and portrait views. The marker is a presentation landmark, has no placement or gate target, and adds no composition or appearance field.

Palette tools persist across placements and occupied-piece selections. A highlighted piece is independent of the active tool: each open-slot click with a tool creates a new stable piece ID. Clicking the active tool again or Escape outside a drag exits placement. Highlighting alone never authorizes relocation. Existing-piece drags originate at that piece; the explicit Move action provides the non-drag destination-click alternative and exits placement mode. Invalid/cancelled gestures preserve the model. Clear/load reset transient tool, selection, and drag state.

The trash target accepts a release from a moved existing-piece drag, including after leaving the canvas. Hovering, cancelled input, and palette-to-trash drops do not modify the scene. Trash and selected-piece deletion share the ordinary undoable edit path and existing audio/output cancellation rules.

Trackball camera rotation changes camera orientation and its up vector without changing composition coordinates. Repeated turns can cross both poles with no upright reset. Zoom remains bounded to camera distances 2.3–5.5. Pointer ownership separates pieces from camera gestures; camera cancellation completes capture/listener cleanup. Composition controls remain in the left panel. Top-right **Reset view** restores the initial camera position, up vector and zoom and stops slow rotation. **Slow rotate** toggles a camera orbit around the current up vector at one revolution per 120 seconds, preserving tilt and zoom. It uses presentation time independently of musical transport and pauses during camera, piece and gate gestures and while the page is hidden. Camera state and the rotation toggle are not serialized and never change composition or output coordinates. One trash button in the selected-piece editor serves both click deletion and drag-to-delete.

## Live-output timing gate

Measure actual browser output with loopback capture (or physical loopback recorded on the reference laptop), against independent analytic onset expectations. Estimate fixed output latency from isolated onset probes, then remove ONLY that measured constant. Required ≥120 onsets across F02/F03, F06 and maximum-supported F08, including 100/250ms main-thread scheduling stalls: compensated onset error median ≤5ms, p95 ≤10ms, maximum ≤20ms; no missing/duplicate ordinary events. Deliberate audio-thread suspension instead exercises explicit interrupted/pause recovery. Scheduled timestamps and offline PCM tests do not pass this gate. Record audio route, sample rate, browser, measured latency, individual errors and stall times. Until loopback output is captured this remains not run. Visual sync separately requires ≥30 captured audiovisual events, median ≤50ms/p95 ≤100ms with measured output latency compensation.

## Position freshness independent of rendering

Manual relocation commits occupancy immediately; display and source positions interpolate on the shortest surface arc for 120ms (deterministic antipodal tangent). A 50Hz monotonic position-update service owns network positions independently of render FPS. Send initial positions before events; update moving objects every 20ms, settle with a final update. Coalesce unsent movement to the newest position per object; if WebSocket bufferedAmount exceeds 64KiB, stop sending updates and retain only newest per object. Resume with a full latest-position snapshot; after 500ms congestion disconnect and watchdog-release. Never coalesce trigger/cancel messages; bounded reliable control backlog failure disconnects visibly. Receiver sequence rejection is per stream (control vs positions), so position coalescing cannot erase musical controls.

Compare actual receiver traces at 60/15/2 FPS: ≤40ms p95 position age on loopback, ≤60ms max, final position within 1e-6, no stale regression, unchanged object IDs, cardinal transform correct. Clock uncertainty ≤10ms and receiver onset p95 ≤20ms are separate gates. Renderer-specific venue interpolation remains unqualified until Steps11–13. Browser heartbeat 100ms; receiver watchdog 500ms; disconnect/reset stops pending remote work and releases objects. Reconnection sends a new session snapshot and never replays missed triggers.

## Toy interface and legacy saved songs

The palette exposes only Generator and the five Harmony Bloom sampled instruments. Earlier note pieces become piano; earlier beats become pitched marimba at the application boundary. Volume and Tempo are global; Spark travel is edited per generator; key, scale and rhythm-grid metadata are retained in files but have no UI controls. A version-one generator can carry an optional path of 2–182 vertex entries, starting at its own vertex and following topology edges. Such a generator emits one particle along that path with the same constant-speed timing as other routes. Moving it clears the path. Choosing Use automatic routes in the app clears it too. Emitted journeys keep their committed paths. F11–F14 play short melody phrases using this mechanism, with each note represented by an editable instrument.

In version-one scenes, generator travel is an optional fraction in [0.25, 0.75], used for both route and legacy radial timing. Older generators without it use the saved scene-level travel fraction; the app copies that value into each generator on load. Future emissions use edits; committed legacy route arrival times remain intact. Current gated generators instead expose whole-hop travel or Infinite. Friendly piece labels are saved independently of machine IDs, assigned per instrument/generator family, and remain stable across moves, unrelated deletion and history. Changing an instrument assigns a matching available family label.
